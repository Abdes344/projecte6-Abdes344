# 📁 P03: Estructura del repositori

## 📖 Introducció

L’ús de **GitHub** i el control de versions amb **Git** és una competència essencial en el desenvolupament de projectes informàtics.

En aquest projecte, el repositori de GitHub és la base del lliurament final, per tant, és imprescindible mantenir una estructura clara, ordenada i professional.

Cada projecte i producte s’ha de gestionar correctament dins del repositori assignat a **GitHub Classroom**, seguint una estructura comuna que faciliti la revisió i el manteniment.

---

# 🗂️ Estructura obligatòria del repositori

El repositori ha d’estar organitzat per carpetes segons el tipus d’activitat:

## 📌 Exemple d’estructura

```
📦 repositori-projecte
 ┣ 📁 T01
 ┣ 📁 T02
 ┣ 📁 T03
 ┣ 📁 ...
 ┣ 📁 P01
 ┣ 📁 P02
 ┣ 📁 P03
```

---

# 📄 Contingut de cada carpeta

Cada carpeta del repositori ha de contenir obligatòriament:

## 1️⃣ README.md

📌 Fitxer obligatori a cada carpeta.

### Característiques

* Nom exacte: `README.md`
* Format: Markdown (.md)
* Contingut:

  * Descripció de l’activitat.
  * Resum de l’enunciat.
  * Explicació general del treball realitzat.

### Exemple d’estructura dins del README

```markdown
# 📌 T01: Nom de la tasca

## 📖 Descripció
Explicació breu de l’activitat.

## 🎯 Objectius
- Objectiu 1
- Objectiu 2
```

---

## 2️⃣ solucio.md

📌 Fitxer principal amb la solució de la tasca.

### Característiques

* Nom exacte: `solucio.md`
* Contingut:

  * Codi (si s’escau).
  * Explicació tècnica.
  * Enllaços a recursos externs.
  * Captures o referències (si cal).

---

## 3️⃣ Carpeta d’imatges

📌 Recomanat per organitzar evidències visuals.

### Estructura

```
📁 images
```

### Contingut

* Captures de pantalla.
* Diagrames.
* Evidències del treball.

---

# ⚙️ Bones pràctiques de repositori

## 🧹 Organització

* Cada tasca en la seva carpeta.
* Noms coherents i clars.
* Evitar fitxers duplicats.

---

## 📝 Documentació

* Utilitzar Markdown correctament.
* Estructurar amb títols i seccions.
* Evitar blocs de text massa llargs.

---

## 🖼️ Imatges

* Sempre dins d’una carpeta específica.
* Noms descriptius.
* Evitar imatges soltes al repositori principal.

---

## 🔄 Control de versions

* Fer commits freqüents.
* Missatges de commit clars:

  * `Afegit README de T01`
  * `Solució de P02 completada`
* Evitar commits genèrics com “update”.

---

# 🚫 Requisits importants

## ❌ No s’accepta

* Lliurament en repositoris externs a GitHub Classroom.
* Estructura desorganitzada.
* Falta de README.md.
* Absència de solucio.md.
